## [2026-09-23] Выбор города
Проблема: нужен город с открытым GTFS, ≥50 маршрутов, без критичных ошибок.
Варианты: Казахстан (нет официального фида в Mobility Database) / Хельсинки
(463 маршрута, но 2 errors и ~960 МБ — слишком рискованно) / Клайпеда
(68 маршрутов, 0 errors, но без fares) / Каунас.
Выбор: Каунас, Литва, фид mdb-1041 (mobilitydatabase.org/feeds/gtfs/mdb-1041).
Почему: GTFS Validator 8.0.1 → 0 errors, 294 warnings, 25 infos. 69 маршрутов,
966 остановок, 7079 рейсов. Есть fare_attributes/fare_rules — полезно для
вопроса "сколько стоит проезд". Warnings в основном косметические (регистр
названий, необязательные поля).
ИИ: числа на сайте каталога (81 маршрут) разошлись с реальным прогоном (69) —
фид обновляется ежедневно, страница успела устареть. Перепроверено локальным
запуском валидатора.
## [2026-09-25] Ядро MCP-сервера: парсинг GTFS + первые 2 инструмента

Проблема: нужно загрузить GTFS в удобный для запросов вид и сделать первые инструменты (поиск остановки, ближайшие отправления), проверив их через MCP Inspector без модели и без Telegram. Выбор: хранение — SQLite (не pandas): удобные JOIN'ы для будущих запросов с пересадками и фильтрацией по календарю, фид маленький, накладные расходы на настройку не критичны. Сделано: gtfs_loader.py (zip -> SQLite, с индексами), gtfs_queries.py (поиск остановки по координатам/названию через haversine; ближайшие отправления с учётом calendar + calendar_dates + рейсов после полуночи), server.py (обёртка в MCP: find_stop, get_next_departures). Оба инструмента проверены вручную в MCP Inspector на реальных данных Каунаса — возвращают корректные результаты (найдено 5 остановок по запросу "centras"; для одной из них — 5 ближайших рейсов, отсортированных по времени). ИИ: две ошибки допущены и исправлены по ходу.

Библиотека mcp оказалась версии 2.x (новее, чем известно ИИ) — класс FastMCP в ней переименован в MCPServer, путь импорта изменился. Обнаружено по traceback при подключении в Inspector, исправлено по официальному гайду миграции (py.sdk.modelcontextprotocol.io).
DB_PATH в server.py был задан относительным путём ("data/gtfs.db"), из-за чего сервер не находил базу при запуске из папки src (путь резолвился как src/data/gtfs.db). Обнаружено по traceback sqlite3.OperationalError при первом вызове find_stop в Inspector, исправлено — путь теперь строится от расположения server.py через pathlib, не зависит от текущей рабочей папки запуска.
