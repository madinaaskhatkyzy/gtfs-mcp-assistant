# MEMORY — durable project memory: gtfs-mcp-assistant

Верифицированные факты и решения проекта. Пополняется по ходу работы,
когда решение подтверждено (не гипотеза, а факт).

## Окружение
- Python 3.11.9, venv `.venv` в корне проекта
- Node.js 24 + npm — для MCP Inspector
- Java 17 — для GTFS Validator
- Git 2.55, ветка по умолчанию: `main`
- Редактор: VS Code + Claude Code (доступен через подписку Claude.ai)

## Данные
- Город: Каунас, Литва — фид mdb-1041, Mobility Database
- Снапшот: mdb-1041-202609210002.zip (2026-09-21)
- GTFS Validator: 0 errors, 294 warnings, 25 infos
- 69 маршрутов, 966 остановок, 7079 рейсов
- Хранение: SQLite (data/gtfs.db), собирается из zip скриптом gtfs_loader.py

## Архитектура
- MCP-сервер: src/server.py, библиотека `mcp` v2.x
  (mcp.server.mcpserver.MCPServer, НЕ mcp.server.fastmcp.FastMCP —
  переименовано в v2, см. TRACE.md)
- 5 инструментов: find_stop, get_next_departures, get_routes_through_stop,
  get_fare, plan_trip (прямой + одна пересадка)
- Вся логика расчётов — в src/gtfs_queries.py, без ИИ, обычный Python/SQL
- Общая функция разбора даты/времени: _parse_target_datetime() в
  server.py — используется в обоих инструментах, где нужна дата/время
  (важно: раньше было продублировано и там был баг, см. TRACE.md)

## Модель и агент
- Провайдер: Google Gemini API, библиотека `google-genai`
- Модель: gemini-3.1-flash-lite (после перебора нескольких вариантов —
  см. TRACE.md; при повторной сборке проекта ПЕРЕПРОВЕРИТЬ актуальность,
  доступность моделей и лимиты меняются быстро)
- Смена модели — через .env (GEMINI_MODEL), без правки кода
- src/agent.py — CLI-агент с многошаговыми вызовами инструментов
  (MAX_TOOL_STEPS=8) и памятью диалога в пределах одного запуска
- Обязательное правило в system_instruction: при нескольких кандидатах
  от find_stop — не выбирать самой, спрашивать пользователя
- Retry на 429/503 с парсингом предложенной API задержки

## Telegram-бот
- Библиотека: python-telegram-bot v22 (async)
- src/bot.py: один MCP-сервер и одна сессия на всё время жизни бота
- История диалога — per chat_id, независимо для каждого чата
- Геопозиция → текстовый вопрос с координатами → тот же агентный цикл

## Проверочный контур
- evaluation/questions.json — 50 вопросов, 5 категорий по 10-12 штук
- evaluation/check.py, check_trip.py — независимые эталоны напрямую
  из SQLite, без участия бота
- evaluation/run_eval.py — автоматический прогон агента на всех 50
  вопросах, автоматический вердикт для 4 из 5 категорий (keyword-match,
  задокументированы ограничения метода), trip_planning — ручная проверка

## Ограничения задания (не переоткрывать без причины)
- Модель НЕ считает расписание сама — все вычисления в MCP-сервере
- Ни одного факта о расписании без вызова инструмента
- "Не знаю" — валидный ответ, когда данных нет
- Проверочный контур запускается одной командой, без Telegram
- Ключи (Telegram, модель) не коммитятся в Git (.env в .gitignore)
- Смена города = замена одного файла фида, без переписывания кода
